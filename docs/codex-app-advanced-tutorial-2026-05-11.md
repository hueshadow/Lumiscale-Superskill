## 场景 1：办公四件套 — 一句话生成 Word/PDF/PPT/Sheets

### 核心价值

告别手动排版——用 Codex 一句话生成排版精美、数据准确的办公文件四件套。

### 实战 Prompt 模板

```
请在当前对话里做一个办公四件套演示任务，主题是《Codex App 内容生产工作流》。
要求：
1. 生成 Word 文档、PDF 文件、PPTX 演示稿、XLSX 表格四类真实文件
2. 每个文件都要有实际内容，不要空文件
3. 生成后告诉我每个文件的真实路径
4. 尽量生成一个预览或文件清单，方便我截图放进教程
5. 最后给出验收清单，确认四个文件都存在、能打开、不是占位内容
```

### 验收结果

逸尘实测 Codex 在没有额外 Skill 和优化 Prompt 的情况下成功生成并验收通过 Word、PDF、PPT、Sheets 四个文件。

### PPT 进阶：两种流行路线

#### 路线一：图片型 PPT
- **原理**：让 Codex 生成一张张 16:9 视觉图片，再把这些图片铺到 PPT 里，每一页本质上是一张完整图片
- **底层**：GPT-2 Image
- **优点**：视觉效果好，不需要排版技能
- **可编辑性**：并非无法编辑，有方法可以后处理

#### 路线二：HTML 型 PPT（当前最火）
- **原理**：用 HTML/CSS/JS 直接写幻灯片，绕过传统 PPT 软件
- **优势**：
  - 浏览器直接预览
  - 支持动画和交互
  - 代码控制布局
  - 方便截图、导出、录屏
  - 与 Codex 天然适配
- **获取方式**：用 Grok 搜索 X 上的开源 Skill，直接让 Codex 安装使用

## 场景 2：3D 视频制作 — Codex 全链路自动化

### 核心价值

验证 Codex「自动写脚本 → 搜索素材 → 自动下载 → 自动识别高光片段 → 自动配音 → 自动剪辑」完整链路。

### 技术栈组合

| 组件 | 作用 |
|------|------|
| Codex | 写项目、改代码、跑渲染、排查错误 |
| three.js | 3D 画面渲染 |
| Minimax | 旁白配音 |
| yt-dlp | 下载视频素材 |
| Remotion / HyperFrames | 网页动画转视频 |
| 本地工具 | 统一音量 |

### 通用视频制作 Prompt 模板

```
目标：
受众：
目标平台：unspecified / YouTube / Shorts / Reels / TikTok / 官网 / 会议现场
时长：
比例 / 分辨率 / FPS：
语言：
场景数量与每场时长：
主体 / 角色：
动作：
场景 / 背景：
镜头 / 构图：
光线 / 色彩 / 风格：
字幕 / 画面文字：
音频：旁白 / 语言 / 音色 / 语速 / 音乐 / SFX
转场：
关键帧 / 参考图 / 角色一致性资产：
品牌 / 法务 / 无障碍：
数据变量 / 占位符：
输出要求：先给 scene list，再给 final prompt，再给 render metadata JSON
```

### 实操步骤

1. **提出需求**：把视频需求清晰告诉 Codex，让它自己去网上找素材下载
2. **信息对齐**：告诉 Codex「如果有任何不清楚的地方，或需要我判断的地方，请一定要停下来问我」
3. **开启权限**：开启「超高」模式 +「完全访问权限」
4. **迭代修改**：得到成片后，把不满意的地方告诉 Codex 修改

### 商业化迁移

将自动化链路迁移到真实商业场景：
- 调用 GPT-2 Image、Seedance 2.0、ElevenLabs 等 API
- 90% 自动化完成视频生产
- 赋能 AI 流量变现、AI 电商带货、AI 前端获客、AI 广告宣传

## 场景 3：网站搭建 + 模型对比实验

### 核心价值

用 Codex 写代码、部署网站、同时用它操控 OpenRouter 测试新模型能力。

### 网站搭建 Prompt 模板

```
请重新帮我生成一个网站，主题是早睡早起。
要求：
1. 页面要排版精美
2. 可以有 3D 动画效果
3. 分析早睡早起的好处
4. 给出普通人能执行的步骤
5. 做成真实可运行的网站
6. 最后启动本地预览，并部署到 Vercel
```

### 部署要点

- Vercel 部署需要先配置插件（Codex「插件」里搜索 Vercel 即可）
- 选择「计划模式」先出方案再写代码，效果更好
- Codex 生成的不只是静态页面，包含：
  - 3D 昼夜节律视觉场景
  - 早睡早起好处说明
  - 晚间关机流程 / 早晨启动流程
  - 7 天调整计划
  - 自测打分 + 常见误区 + 参考资料

### 白嫖网页版 AI 的技巧

**核心思路**：打开网页版 AI（ChatGPT Pro、Ring 等），把需求告诉它，让它返回代码，Codex 负责执行和部署。

**案例**：用 Codex 操控浏览器，在 OpenRouter Chat Playground 选 Ring-2.6-1T (free)，把网站 Prompt 和本地 frontend-design skill 审美原则丢给它生成 HTML，再部署到 Vercel——完全白嫖 Token。

**迁移思路**：Codex 只能用 GPT-5.5 模型，但网页端可以用 GPT-5.5 Pro，通过这个思路能让 Codex 间接调用更强的模型。

## 场景 4：自媒体图文教程 — 让 Codex 写爆款文章

### 核心价值

逸尘上一篇 92W 阅读的《Codex App 从0到1完整入门教程》80% 由 Codex 完成——包括文章、截图、打码、配封面图。

### 为什么别人用 AI 写出的是「一坨」？

**根因**：Codex 不知道你的知识结构、审美偏好、目标读者的认知水平。你给方向，它就自由发挥；你给思路，它就加速执行。

### 正确写作方法

| 步骤 | 操作 |
|------|------|
| 1. 搭框架 | 核心观点 → 文章结构 → 每段要点（一句话） |
| 2. 给 Prompt | 把框架作为提示词给 Codex，让它「加速流程」而非「从零创作」 |
| 3. 沉淀 Skill | 用过去高质量文章提炼写作风格 Skill |

### 实战 Prompt 示例

```
你来操作Codex APP本身，你挨个分析Codex主界面每个按钮的功能，
然后再打开Codex的设置，按照左边导航栏的顺序，一页一页仔细地介绍。
注意把隐私的地方打码。
```

### 进阶操作：多对话并行

让 Codex 同时开几个对话窗口跑任务，自己监控自己——大幅提高效率。

## 场景 5：电商自动化上架 — Codex + Playwright 实战

### 痛点场景

- 链接数量多，每个链接下有多个 SKU
- 表格几千行数据，在售链接几百个
- 开新店需要重建几百个商品链接
- 每个 SKU 需填库存、拼单价、规格编码、商品编码、参考价等字段
- 人工填写慢且容易出错

### 方案演进：Computer Use → Playwright

| 方案 | 原理 | 适用场景 | 限制 |
|------|------|----------|------|
| Computer Use | 看屏幕 + 模拟键鼠 | 开放网站（Google、文档、X） | 被拼多多等反爬平台拒绝 |
| Playwright | Chrome DevTools Protocol 操控浏览器内核 | 有反爬保护的后台系统 | 需要编程基础（Codex 能写） |

### 完整自动化链路

```
商品底表 → 整理字段映射 → Playwright 打开后台 → 填写商品基础信息
→ 填写 SKU 价格和库存 → 上传图片和视频 → 截图暂停人工确认
→ 确认后批量运行 → 输出成功/失败日志 → 沉淀为 Skill
```

### Codex 负责的整条链路

1. 读取原始 Excel，分析哪些列有用
2. 重新整理成标准上架表
3. 确认字段映射
4. 写 Playwright 自动化脚本
5. 用已登录浏览器打开后台
6. 先跑一个商品，截图暂停让人工确认
7. 记录成功/失败和错误截图
8. 稳定后批量跑
9. 把流程沉淀成 Skill → 「一次性填表」升级为「公司可复用的自动化流程」

## 常见踩坑与解决方案

### 坑 1：Computer Use 被反爬平台拒绝

**现象**：让 Codex 用 Computer Use 操作拼多多后台，直接被拒绝访问

**根因**：部分网站检测自动化操作（浏览器指纹、WebDriver 标记、无头模式等），Computer Use 与真人行为模式有差异

**解法**：
- **首选 Playwright**：走 CDP 操控浏览器内核，配合 `stealth` 伪装
- **复用已登录浏览器**：让 Playwright 连接已登录 Chrome 实例（`--remote-debugging-port`）
- **分工策略**：Computer Use 用于开放网站，Playwright 用于有反爬保护的后台

### 坑 2：无法操控外部终端

**现象**：想让 Codex 操作本机 Ghostty / Claude Code 终端，只能看屏幕不能接管输入

**根因**：Codex Computer Use 能识别屏幕内容，但不能向外部终端进程发送命令

**绕路办法**：
- 如需网页版 AI 能力，直接打开网页版操作
- 如需 CLI 命令，在 Codex 内置终端直接执行
- 「让 Codex 调用 Claude Code」目前不可行，需等白名单放宽

### 坑 3：AI 写作输出质量差

**现象**：跟 Codex 说「帮我写一篇关于 XX 的文章」，输出是一坨

**根因**：Codex 缺少你的知识结构、审美偏好、读者认知水平

**解法**：
1. 写之前自己搭框架（核心观点 → 结构 → 每段要点）
2. 把框架给 Codex 让它「加速执行」
3. 沉淀写作风格 Skill（用过往高质量文章提炼）

### 坑 4：代理配置导致连接失败

**现象**：Codex 对话出现连接错误

**解法（四步走）**：
1. 不要只配 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`，还要补 `WSS_PROXY`/`WS_PROXY`（新对话可能走 wss://）
2. 代理变量写进 `~/.codex/config.toml`
3. 用 `launchctl setenv` 写进 macOS 图形应用启动环境
4. 完全退出 Codex 再重新打开（不是只关窗口）

## 推荐学习路径

如果刚开始用 Codex App，不要一上来就挑战最复杂的电商自动化。建议按以下顺序：

| 阶段 | 任务 | 目标 |
|------|------|------|
| 1 | 生成几张图片 | 建立基本信任 |
| 2 | 生成 Word/PDF/PPT/XLSX | 体验文档生成能力 |
| 3 | 做一个 HTML 小网页 | 接触代码生成 |
| 4 | 启动本地预览 | 理解代码运行 |
| 5 | 部署到 Vercel | 掌握上线流程 |
| 6 | 做图文教程 | 自媒体内容生产 |
| 7 | 尝试 HTML PPT | 进阶排版能力 |
| 8 | 尝试视频动画 | 多媒体生产 |
| 9 | 业务自动化 | 真实商业场景 |

按照这个顺序，你会逐步建立和 Codex 的信任——先看到它能生成资料、网站，看到它上线，看到它操作浏览器，最终理解 Codex 不是一个聊天框，而是无所不能的超级助手。

## 关键洞察

1. **Codex 不是聊天框** — 它是能操控浏览器、执行代码、调用 API 的超级助手
2. **「你给思路，它加速执行」优于「你给方向，它自由发挥」** — 写作/创作的正确打开方式
3. **Computer Use 和 Playwright 有明确分工** — 前者适合开放网站，后者适合有反爬保护的后台
4. **成功的经验要沉淀成 Skill** — 从「一次性任务」升级为「公司可复用的自动化流程」
5. **学习路线要循序渐进** — 从图片生成到业务自动化，逐步建立信任
