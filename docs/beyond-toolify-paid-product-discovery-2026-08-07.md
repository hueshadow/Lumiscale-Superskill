# Toolify 以外：系统找「有付费收入」的产品

> 整理时间：2026-08-07  
> 适用场景：赛道扫描、竞品对标、需求真伪校验、蓝海供给审计  
> 与 Toolify 收入榜关系：榜单 = 头部校准与红海地图；本文 = 榜外「已在卖 / 像有收入」的发现路径  
> 来自hueshadow

---

## 0. 先定证据等级（否则只会收藏链接）

找「有付费收入」时，**收入数字几乎永远估不准**；可操作目标是建立**可复核的付费证据链**，再决定深挖。

| 等级 | 含义 | 典型证据 | 决策权重 |
|------|------|----------|----------|
| **S** | 强付费事实 | 自报 MRR/ARR + 截图或 Stripe 叙事；App 商店订阅档 + 收入估工具交叉；明确案例客户+合同制 B2B | 最高：可进对标池 |
| **A** | 高置信「在卖」 | 官网可走完结账（Stripe/Paddle 等）；G2/Capterra 多条「付费后」评论；LTD 已售罄/有销量 | 高：可当有收入产品 |
| **B** | 中置信商业化 | 明确 Pricing 页 + 月访可观 + Freemium/Paid 标签；融资 + 上线收费页 | 中：需二次核验 |
| **C** | 弱信号 | 仅目录标 Paid；仅有 Contact sales；仅融资新闻无产品页 | 低：不能当「有收入」 |

**原则：**

1. **官方披露 / 真结账 > 支付探针 > 套餐+流量+评论 > 仅目录标签**  
2. 融资 ≠ 收入；流量 ≠ 付费；Pricing 页 ≠ 有人付钱  
3. 国内对公转账、企业微信成交、代理分销等，**西方探针常扫不到**——要用本地评论/案例/应用商店补  
4. 目标若是「找领地」而非「抄榜」：有付费只是 **L3 供给审计** 的输入，还要叠需求真 / 供给薄 / 你能站住

## 1. 总工作流（每周可复用）

```
Step 1  定范围：品类关键词 × 客群 × 价格带假设
        ↓
Step 2  广采候选（本文 11 源，每周选 4～6 源深挖，勿 11 源全浅刮）
        ↓
Step 3  证据分级 S/A/B/C + 去重（域名 / 产品名 / 母公司）
        ↓
Step 4  快核：Pricing 是否可结账？买家是谁？结果卖什么？
        ↓
Step 5  入库字段（见附录 A）→ 只把 S/A 送进竞品卡或供给密度分
        ↓
Step 6  与 Toolify 交叉：在榜=红海校准；不在榜但有 S/A=榜外宝藏或小而美
```

**配额建议（个人研究者）：**

- 每周新增 **≥15 个** 有 A 级以上证据的候选（不必深写）  
- 其中 **3～5 个** 做成一页竞品卡  
- 每周 **杀死 ≥5 个**（写清理由：伪付费 / 纯套壳 / 你站不住）

## 2. 方法详表（可落地）

### 2.1 Stripe 公开叙事 / 博客 / 客户故事

| 项 | 内容 |
|----|------|
| **适合找什么** | 增长很快的 AI SaaS、支付已规模化的公司、到关键 ARR 里程碑的案例 |
| **不适合** | 非 Stripe 栈、对公/本地支付为主、极早期未公开 |
| **入口** | stripe.com/blog、stripe.com/customers、stripe.com/newsroom；搜 `site:stripe.com AI` / `ARR` / `$1M` / `million` |
| **怎么用** | 1）扫客户故事与「AI 收款增速」类文章 2）抽出公司名 → 官网 Pricing 3）记里程碑（$1M/$10M/$30M ARR 叙事）作**量级锚**，不作精确财报 4）看他们强调的支付能力（订阅、用量计费、全球结算）反推商业模式 |
| **证据等级** | 叙事本身多为 **B～A**；若同时官网可结账 → 升 **A** |
| **搜索词** | `Stripe AI startup customers`、`Stripe "$1M" ARR AI`、`site:stripe.com generative AI` |
| **坑** | Stripe 案例有 PR 滤镜；「用 Stripe」≠「收入高」；注意故事年份 |

### 2.2 GetLatka / Sacra / Contrary Research 等私营公司库

| 项 | 内容 |
|----|------|
| **适合找什么** | 有 **ARR 区间** 的私营 SaaS/AI；按赛道浏览「谁已经到规模」 |
| **不适合** | 超早期、纯中文市场、未进英语分析师视野的产品 |
| **入口** | getlatka.com、sacra.com、contrary.com/research 等（权限/付费墙各异） |
| **怎么用** | 1）按关键词/赛道搜公司 2）记录 **ARR 区间、团队规模、增速、定价线索** 3）回官网核 Pricing 与 ICP 4）同赛道拉 5～10 家做价格带直方图 |
| **证据等级** | 第三方估数为 **B**（方法不透明）；多家交叉 + 官网收费 → 可当 **A 的量级参考** |
| **搜索词** | 公司名 + `Latka` / `ARR`；赛道名 + `Sacra` |
| **坑** | 估数滞后、口径不一；免费可见字段有限；**不要把区间中值当事实** |

**替代/补充（同类情报）：**  
Crunchbase/PitchBook（融资向）、LinkedIn 招人密度（侧面）、公司 Careers 页「我们服务 X 客户」文案。

### 2.3 AppSumo / PitchGround（及同类 LTD 平台）

| 项 | 内容 |
|----|------|
| **适合找什么** | **已验证有人愿付费** 的工具（尤其 SMB/独立开发者向）；lifetime deal 销量是强行为信号 |
| **不适合** | 高客单企业销售型；强合规/医疗金融（常不上 LTD） |
| **入口** | appsumo.com、pitchground.com；可看「Sold out」「X sold」 |
| **怎么用** | 1）按 AI / 品类浏览在售与历史 2）记录 deal 价、官方原价锚、评价数、是否 sold out 3）点进官网看是否仍卖订阅（LTD 后产品是否活着） 4）读差评：「退款原因」常是真需求边界 |
| **证据等级** | 有明确销量/售罄 → **A**；仅上架无数据 → **B** |
| **坑** | LTD 用户 ≠ 长期订阅用户；有的产品靠 Deal 脉冲后死亡；质量参差，需看更新日志 |

### 2.4 Product Hunt +「Pricing」

| 项 | 内容 |
|----|------|
| **适合找什么** | **新品商业化** 信号、早期定位话术、评论区真实吐槽 |
| **不适合** | 精确收入；大量 launch 是营销事件无持续收入 |
| **入口** | producthunt.com；产品页 Topics；搜产品名 |
| **怎么用** | 1）新品/相关 Topic 列表 2）产品页与评论搜 `price` / `pricing` / `plan` / `expensive` / `cancelled` 3）**必须**点官网 Pricing 复核 4）看 Maker 是否回复定价异议（认真做商业化的信号） 5）收藏「Launch 后 3～6 个月仍活跃」的，降权一日游 |
| **证据等级** | 评论提到已付费 + 官网可购 → **A**；仅有 Pricing 链接 → **B** |
| **搜索词** | `site:producthunt.com AI pricing`；PH 站内 Topics + 人工点开 |
| **坑** | 点赞≠付费；假评论；「Coming soon pricing」 |

### 2.5 G2 / Capterra（及同类评论站）

| 项 | 内容 |
|----|------|
| **适合找什么** | **真有付费用户** 的 B2B/SaaS；可对比满意度与未满足点 |
| **不适合** | 纯 C 端小工具、无英文市场产品 |
| **入口** | g2.com、capterra.com；按 Category 浏览 |
| **怎么用** | 1）锁定品类 2）筛评论量（如 >20 / >50） 3）全文搜付费向表述：`paid` `subscription` `plan` `invoice` `ROI` `switched from` 4）记录「从竞品 X 换到 Y」对图谱 5）差评里的重复缺口 = 供给结构机会 |
| **证据等级** | 多条已验证买家评论 → **A**；评分少或疑似邀评 → **B/C** |
| **坑** | 厂商引导好评；分类脏；免费用户也会评——优先看写了套餐/采购流程的长评 |

### 2.6 Similarweb / Semrush（流量侧证）

| 项 | 内容 |
|----|------|
| **适合找什么** | **流量质量与规模**；「高访 + 明确 Pricing」≈ 至少在卖或认真获客 |
| **不适合** | 私域/插件/App 为主、官网只是壳的产品（会严重低估） |
| **入口** | similarweb.com、semrush.com（免费档有限） |
| **怎么用** | 1）查域名月访、国家分布、获客渠道 2）看是否有 `/pricing` 进入路径与品牌词 3）同品类 5 个域名横比 4）流量突然抬升 + 新 Pricing = 值得跟踪 |
| **证据等级** | 单独最多 **B**；叠加可结账/评论 → 支撑 **A** |
| **坑** | 估数误差大；下载站/文档站虚高；B2B 低访高 ARPU 会被误杀——**低流量不要直接判死刑** |

---

### 2.7 BuiltWith / Wappalyzer（技术栈侧证）

| 项 | 内容 |
|----|------|
| **适合找什么** | 站上挂了 **Stripe.js / Paddle / Chargebee / Recurly / Lemon Squeezy** 等 → 支付基建就绪 |
| **不适合** | 仅用 mailto 下单、微信收款码、应用内购为主 |
| **入口** | builtwith.com、浏览器 Wappalyzer 扩展；也可看网页源码/网络请求里的 `js.stripe.com` |
| **怎么用** | 1）候选域名扫支付/订阅相关技术 2）正向上：已知品类批量扫 3）发现支付栈后回看 Pricing 与结账是否真通 4）可做「品类内谁已上订阅引擎」清单 |
| **证据等级** | 有支付 SDK = **B**；能完成测试结账 = **A** |
| **坑** | 装了 Stripe 但只收捐赠；历史残留脚本；Checkout 在别的子域 |

**快速手工探针（无付费工具时）：**  
打开站点 → 定价页 → 开发者工具 Network，点 Upgrade，看是否跳转 Stripe/Paddle Checkout。

### 2.8 Chrome 扩展店 / 移动应用商店

| 项 | 内容 |
|----|------|
| **适合找什么** | **非纯网站** 产品：扩展、iOS/Android；内购与订阅档是公开的 |
| **不适合** | 纯 Web SaaS（应回官网）；企业私有分发 |
| **入口** | Chrome Web Store；App Store；Google Play；收入向：Sensor Tower / data.ai / Appfigures 等（偏移动） |
| **怎么用** | 1）品类关键词搜 2）看「含应用内购买/订阅」标签 3）记录订阅档位与评论里的涨价/取消 4）移动端用估收工具做 **量级排序**（非精确） 5）扩展看用户数 + 付费解锁描述 |
| **证据等级** | 明确订阅档 + 大量「付费后」评论 → **A**；仅有 IAP 标签 → **B** |
| **坑** | 商店收入含退款与分成前；买量刷量；扩展「用户数」含水 |

| 项 | 内容 |
|----|------|
| **适合找什么** | **已融资且产品已上线收费** 的公司；案例客户与 ICP 叙事 |
| **不适合** | 当收入证明（融资是燃料不是 ARR） |

| **坑** | 「AI 包装融资」无产品；Pricing 仅 Contact sales 时要区分 **高客单 B2B**（可能很有钱）与 **还没卖** |

## 3. 组合拳：按目标选源（不要平均用力）

| 你的目标 | 优先源（顺序） | 产出 |
|----------|----------------|------|
| 找「已验证愿付费」的中小工具 | AppSumo → 独立开发者报收 → PH → 官网结账 | A 级清单 + 价格带 |
| 找高速 AI SaaS 对标 | Stripe 叙事 → Latka/Sacra → Similarweb → G2 | 量级锚 + ICP |
| 找 B2B 真买家声音 | G2/Capterra → 融资+案例 → Book demo 流程 | 差评缺口 + 换竞品图 |
| 找非 Web 形态 | 应用商店/扩展店 → Sensor Tower 类 → 官网 | 订阅档 + 估收序 |
| 榜外小而美 | X/Reddit 报收 → LTD → 目录 paid 筛 → BuiltWith | Toolify 未覆盖池 |
| 供给密度审计（领地） | 目录+PH+商店数量 → 功能同质 → 差评同一缺口 → 站外 S/A 需求信号 | 薄/厚判断 |

## 4. 单品 15 分钟快核清单

对任意候选域名，严格计时，超时就标「待核」入库：

1. **30 秒**：一句话做什么？买家角色？  
2. **2 分钟**：有无 Pricing？Free / Trial / Paid / Sales-led？  
3. **3 分钟**：能否看到真实结账或明确销售转化（演示预约也算 B2B 路径）？  
4. **3 分钟**：G2/商店/PH 是否有「已付费」表述？  
5. **3 分钟**：支付栈或商店 IAP 线索？  
6. **3 分钟**：证据等级 S/A/B/C + 是否在 Toolify 收入榜头部？  
7. **尾声**：杀死 or 进竞品卡？**必须写一句理由**

## 5. 与 Toolify 收入榜如何配合

| Toolify 用途 | 做法 |
|--------------|------|
| 红海地图 | 头部品类与话术同质簇 → 你的候选若落在簇心默认降权 |
| 定价带 | 分类 Pricing 学 $9/$29/$99/销售导向 |
| 供给空洞 | 站内可检索少或 80% 同质且关键步仍人工 |
| **不要** | 把收入榜当「所有赚钱产品全集」；不在榜 ≠ 没收入 |

**榜外仍有收入的常见原因：**  
体量未进探针头部；自建/本地支付；B2B 合同制；App 内购为主；私域成交；刚开收费。

---

## 6. 反模式（做了等于没做）

1. 只存书签不写证据等级  
2. 把融资新闻当 ARR  
3. 只信单一目录的 Paid 标签  
4. 用 Similarweb 杀掉所有低访 B2B  
5. 收集 200 个工具却 0 个完成结账探针  
6. 不与 Toolify 去重，重复研究头部壳产品  
7. 为「找付费产品」而找，忘记是否 **需求真 / 供给薄 / 你能站住**

---

## 7. 建议双周节奏

**第 1 周：采与核**

- 选 4 源深挖（例：G2 品类 + PH 新品 + 1 个报收搜索 + 1 次目录 paid 筛）  
- 完成 ≥15 条 A/B 入库，≥5 条 A 级快核  

**第 2 周：结构与杀死**

- 聚类成 3～5 个「功能簇」  
- 每簇标价格带、同质度、差评缺口  
- 只留 1～2 个进入需求结构卡 / 验证阶梯  
- 更新「已杀死」列表防反复爱上

## 附录 D：和「需求挖掘」的接口

本文解决：**谁已经在收钱（供给侧样本）**。  
领地决策仍须：

- **需求真**：站外 S/A 信号（已有人花钱/花时间的笨办法）  
- **供给薄**：同质簇与差评缺口，而非「目录里产品个数」  
- **你能站住**：洞察/渠道/资产/约束利用  

有付费的红海产品 → 用来学定价与话术，默认不进主战场。  
有付费但供给结构薄（关键步仍人工、差评同一洞）→ 才是楔子候选。
